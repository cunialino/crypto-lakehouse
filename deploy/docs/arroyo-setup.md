# Arroyo migration (RisingWave → Arroyo 0.15.0)

Deploys [Arroyo](https://arroyo.dev) 0.15.0 via ArgoCD (chart `arroyosystems/helm-repo`, app `arroyo`) to consume NATS `tradesstream` (protobuf `trade.data.TradeEventProto`), write traded Iceberg data to Lakekeeper `trades.trades` (Garage S3 backed), and emit a trade-gap approximation to NATS core subject `trade.gaps`.

## Prerequisites (done in earlier steps, not this repo)

- CNPG provisioning in `~/builds/homelab/base/cnpg/` (Database `arroyo` on `pg-cluster`, managed role + `arroyo-metastore-secret` ExternalSecret reusing bitwarden `c2819f29-de3f-4b10-bd81-b3e7015fee88`).
- Sync `cnpg.yaml`/`cluster.yaml` in the homelab ArgoCD before the arroyo app.

## Manual step: Garage bucket `arroyo001`

`create_bucket.yaml` is not used; the bucket must be created manually once, via the garage CLI inside the garage pod:

```sh
# inside the garage namespace
kubectl -n garage exec deploy/garage -- garage bucket create arroyo001

# grant the shared lakekeeper/arroyo S3 keys access (these are the bitwarden
# id 05c2c173-3de5-4727-80a5-b416016a3c73 / secret 01c16d85-1a29-4581-b417-b416016a58fa)
kubectl -n garage exec deploy/garage -- garage bucket allow \
  arroyo001 --read --write --key <garage-key-id-for-those-creds>
```

The controller stores checkpoints at `s3::http://garage-svc.garage.svc.cluster.local:3900/arroyo001/checkpoints` and compiled artifacts at `.../arroyo001/artifacts`, so do this **before** the `arroyo` app syncs.

## Secrets

- `rustfs-secret` (ns `arroyo`): AWS/Garage S3 creds (reused from RisingWave), plus minio user/password.
- `arroyo-metastore-secret`: DB password for `arroyo` (bitwarden `c2819f29-...`), same value as the CNPG managed role.
- `arroyo-api-key` (new): static API key for the Arroyo REST API. **Replace the placeholder bitwarden UUID in `deploy/base/arroyo/api_secret.yaml` with a real entry before syncing.**

## REST register job

`deploy/base/arroyo/pipelines-register-job.yaml` is a `Sync` hook Job running `register.sh` (mounted
from the `arroyo-pipelines` ConfigMap generated by `deploy/base/arroyo/kustomization.yaml` via
`configMapGenerator` from `proto/`, `sql/`, `register.sh`). It is idempotent and:

1. Waits for `http://arroyo:80/api/v1/connectors` to answer with the bearer key.
2. Validates the protobuf schema (`POST /connection_tables/schemas/test`) and every `sql/*.sql`
   (`POST /pipelines/validate_query`); aborts the sync on any error.
3. Creates connection profiles: `nats_cluster` (NATS, auth none), `lakekeeper_catalog` (Iceberg REST catalog, warehouse `crypto`, no token).
4. Creates connection tables:
   - `nats_trades` — source, JetStream `tradesstream`, protobuf schema inlined from the mounted proto (bad-data = drop).
   - `iceberg_trades_sink` — sink, `trades.trades_2`, partitioned `identity(exchange), day(trade_ts)`, storage options pointing at Garage.
   - `trade_gaps_sink` — sink, core NATS subject `trade.gaps`, JSON.
5. Creates pipelines `arroyo-lakehouse` and `arroyo-trade-gaps` (parallelism 1, 10s checkpoint), skipping any that already exist.
6. If git SQL/proto differs from what is registered, the drifted pipeline is
   stop(force) -> delete -> recreated (full JetStream replay). A git SQL/schema change therefore
   deploys with a single push; broken artifacts fail `validate_query`/`schemas/test` before any
   recreate happens.

Protobuf cannot be declared in `CREATE TABLE` in 0.15 (`ProtobufFormat::from_opts` rejects it), hence the REST-based source registration.

## Verification

```sh
# API (StaticApiKey)
curl -H "Authorization: Bearer $ARROYO_API_KEY" http://arroyo:80/api/v1/pipelines

# jobs
kubectl -n arroyo get pods -l app=arroyo-worker   # 4 slots / 4 parallelism
kubectl -n arroyo logs deploy/arroyo-controller

# NATS gaps subject (core)
kubectl -n nats exec deploy/nats-0 -- nats sub trade.gaps -s nats://nats:4222
```

## Known notes / follow-ups

- Iceberg sink loads the existing `trades.trades`; its partition spec must match `identity(exchange), day(trade_ts)` and column types (timestamps must align with the table, `to_timestamp_micros`). Verify first run commit / column ids.
- Dedup is done by Spark maintenance (`query.py`/`tmp.py`), not in Arroyo.
- The gaps pipeline is an approximation (processing-time tumbling window), not the exact RW `LAG() OVER` MV — arroyo 0.15 requires windowed input for OVER functions.
- `deploy/base/risingwave/*` and `deploy/apps/risingwave.yaml` are kept for reference; retire after cutover. `dbt_model/profiles.yml` uses `type: risingwave` and will become invalid once RW is removed.
- PrometheusRule for `arroyo_*` metrics (controller 5114/metrics, workers 6901/metrics) is still TODO.
